# Portfolio Parameter Optimization

This directory contains automation scripts for finding optimal parameter combinations for the portfolio optimization process.

## Goal

Maximize expected return while maintaining Sharpe ratio > 0.9

## Overview

The optimizer performs random search across parameter combinations, running `opt3.py` with the `-x` flag (no database writes, no downloads) to test different configurations. Results are accumulated in `optimization_results.json` for analysis.

## Parameters Being Optimized

1. **gamma** - Regularization parameter for L2_with_weight_smoothing
2. **rgoal** - Target volatility/risk goal for efficient_risk optimization
3. **lb** - Lower bound for individual asset weights
4. **ub** - Upper bound for individual asset weights

## Files

- `optimizer.py` - Main optimization wrapper script
- `param_ranges.json` - Parameter search ranges configuration
- `optimization_results.json` - Accumulated results (created after first run)
- `gamma_vs_wgtstdev.png` - Visualization plot (generated by `-r`)
- `README.md` - This file

## Quick Start

```bash
# Run 10 iterations (default)
./optimizer.py

# Run 100 iterations
./optimizer.py -n 100

# View results report
./optimizer.py -r
```

## Command-Line Options

```
usage: optimizer.py [-h] [-n N] [-c FILE] [-r] [-b]

options:
  -h, --help            Show help message and exit
  -n, --iterations N    Number of parameter combinations to test (default: 10)
  -c, --config FILE     Path to parameter ranges config file (default: param_ranges.json)
  -r, --report          Display tabular report of all accumulated results and exit
  -b, --bayesian        Use Bayesian optimization guided by existing results
```

### Viewing Results

```bash
# Display comprehensive report
./optimizer.py -r
```

The report shows:
- Summary statistics (total, valid, invalid counts)
- Table of valid results sorted by score
- Detailed best result metrics
- All results with timestamps
- **Bubble chart** of Gamma vs Weights StdDev (bubble size = score)

**Plot Output:** `gamma_vs_wgtstdev.png` is automatically generated in the parameter_optimization directory.

The bubble chart visualizes the relationship between:
- **X-axis:** Gamma (regularization parameter)
- **Y-axis:** Weights StdDev (portfolio concentration)
- **Bubble size:** Score (larger = better)
- **Bubble color:** Score (blue = low, yellow = medium, red = high)

This helps identify sweet spots in parameter space where both gamma and diversification produce high scores. Larger, redder bubbles indicate optimal parameter combinations.

**Note:** Requires `gnuplot`. Install with:
```bash
apt-get install gnuplot  # Debian/Ubuntu
# or
yum install gnuplot      # RHEL/CentOS
```

## Configuration

### Parameter Ranges (`param_ranges.json`)

Edit this file to adjust the search space:

```json
{
  "gamma": {
    "min": 0.0,
    "max": 10.0,
    "description": "Regularization parameter for L2_with_weight_smoothing"
  },
  "rgoal": {
    "min": 0.05,
    "max": 0.20,
    "description": "Target volatility/risk goal for efficient_risk optimization"
  },
  "lb": {
    "min": 0.0,
    "max": 0.05,
    "description": "Lower bound for individual asset weights"
  },
  "ub": {
    "min": 0.10,
    "max": 0.30,
    "description": "Upper bound for individual asset weights"
  }
}
```

You can create multiple config files for different search strategies:
- `narrow_ranges.json` - Focus search around known good values
- `aggressive_ranges.json` - Test extreme parameter values
- `conservative_ranges.json` - Safe, stable configurations

## Results Format

### Metrics Tracked

Each result includes:
- **expected_return** - Annualized expected return
- **sharpe_ratio** - Risk-adjusted return metric
- **volatility** - Annualized portfolio volatility
- **weights_stdev** - Standard deviation of portfolio weights (concentration measure)
- **params** - gamma, rgoal, lb, ub values used
- **timestamp** - When the result was generated

### Composite Score

When viewing results with `-r`, a composite score is calculated for each result:

**Formula:** `Score = (Return × Sharpe) / (Volatility + WgtStdDev × 10)`

This score:
- **Rewards:** Higher expected return and Sharpe ratio
- **Penalizes:** Higher volatility and portfolio concentration (weights_stdev)
- Results are sorted by score (highest = best)

The score provides a single metric to compare portfolios that balances:
- Performance (return, Sharpe)
- Risk (volatility)
- Diversification (weights distribution)

**Example scores:**
- 0.70-0.80 = Excellent (high return, low risk, well diversified)
- 0.60-0.70 = Good
- 0.50-0.60 = Fair
- <0.50 = Poor

### Results Storage

Results are **appended** to `optimization_results.json` across multiple runs. To start fresh:

```bash
rm optimization_results.json
```

## Understanding Results

### Infeasible Results

Many parameter combinations will be "infeasible" - this means the optimization constraints (sector limits, bounds, etc.) cannot all be satisfied simultaneously. This is expected and indicates the feasible parameter space is limited.

### Success Rate

Typical success rates vary:
- 10-40% feasible with default ranges
- Higher success with narrower, well-tuned ranges
- Lower success with aggressive/extreme ranges

### Weights Standard Deviation

Indicates portfolio concentration:
- **0.01-0.02** - Well diversified
- **0.03-0.05** - Moderate concentration
- **>0.05** - Highly concentrated

```bash

```

## Optimization Strategy

The optimizer supports two search strategies:

### Random Search (Default)

**Random search** is:
- Simple and robust
- Parallelizable (can run multiple instances)
- Often performs as well as grid search with fewer evaluations
- Better than grid search for high-dimensional spaces

### Bayesian Search (`-b` flag)

**Bayesian optimization** uses machine learning to intelligently guide the search:
- Learns from existing results to predict promising parameter regions
- Uses Gaussian Process regression to model the score function
- Selects next parameters using Expected Improvement acquisition function
- More efficient than random search (finds optimal solutions faster)
- Requires existing results (minimum 5 runs) to build initial model
- Continuously updates model with new results during the run

**When to use Bayesian search:**
- After accumulating initial random search results (≥5 runs)
- For expensive optimizations where each evaluation takes significant time
- When refining around a promising region of parameter space
- To maximize improvement per iteration

**Dependencies for Bayesian search:**
```bash
pip install numpy scikit-learn scipy
```

**Example:**
```bash
# First, run random search to build initial dataset
./optimizer.py -n 50

# Then use Bayesian search to efficiently explore
./optimizer.py -b -n 30

# View results
./optimizer.py -r
```

## Tips

1. **Start small** - Test with `-n 10` to verify everything works
2. **Monitor infeasibility rate** - If >90% infeasible, ranges may be too wide
3. **Accumulate results** - Run multiple batches, results append automatically
4. **Save good configs** - Copy successful param_ranges.json files
5. **Compare runs** - Use `-r` to analyze trends across batches

## Technical Notes

- Runs `opt3.py` with `-x` flag (no I/O mode)
- Uses existing `pricedataset.csv` from parent directory
- No database writes during optimization
- Results stored in JSON for portability
- Each run adds to cumulative results file
- PNG plotting via `gnuplot` (optional but recommended)
